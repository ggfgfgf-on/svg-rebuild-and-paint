# 构图与迭代观察（可选，不是流程）

这份笔记**不在默认入口**，不要求阅读，也不构成合格线。它只把“看图时容易漏掉的隐含决定”写成可检查的问题，供写 build script 时参考。

## 1. 开画前，先把隐含意图写进注释

不是每个 prompt 都会给机位、地平线、焦点和光线。模型自己定的部分，最好在 build script 顶部写成注释，避免边画边换：

~~~python
# intent:    冷、空、灯塔是唯一暖源
# camera:    低机位，海平线约 55% 高度
# focal:     灯塔灯室；次焦点是浪
# light:     灯室向右扫出锥形光，远处衰减
# foreground: 左下礁石压角，右侧留冷空
# palette:   冷灰蓝 + 一点暖橙
# avoid:     光束和海平线都水平，容易压成两条横带
~~~

这些是**这一张的意图**，不是通用规则。换题材就换注释。

## 2. 迭代时看什么

### 先看缩略图，不要先抠细节

把当前图缩到 25%（例如 1200×900 → 300×225），只问：

- 第一眼落在哪？
- 有几个焦点在抢？
- 主体轮廓还成立吗？
- 负空间是不是比主体更重？
- 有没有一条线把视线带向主体，还是把视线带出画外？

缩略图读不懂，细化不会救回来。

### 一次只改一类

- 构图（位置、地平线、主体大小）；
- 明度（大块亮/暗、焦点对比）；
- 颜色（冷暖、饱和度、光的颜色）；
- 细节（边缘、纹理、反射）。

四类一起改，渲染结果无法归因。

### 每次改完留一张图

不需要强制 checkpoint；但至少保留“改前/改后”两张，避免凭记忆比较。

## 3. 常见失败模式

| 现象 | 通常是什么 |
|---|---|
| 左侧/右侧一大块空，主体贴边 | 负空间没有承担内容，主体只是被挤到边上 |
| 光束、海平线、岸线全是水平线 | 三条平行横带，画面被切成一叠 |
| 光束是矩形雾带 | `screen` 大笔刷近似，不是锥形/方向性衰减 |
| 主体边缘有 8–10px 彩色毛边 | 填充笔刷中心在 polygon 内，半径仍然越界；见 SHAPE_API 边界契约 |
| 25% 看只剩一个剪影 | 大块明度没分开，细节都在 100% 才有 |
| 每个局部都清楚，整体没有第一眼 | 焦点太多，或者最亮处不在主体 |
| 主体和背景交界处“粘”在一起 | 缺少明度/冷暖/边缘分离 |
| 石头、船、塔像贴纸 | 接触面没有投影/遮挡/透视收敛 |

这些不是“必须避免”的规则；出现时知道该查哪一类。

## 4. 什么时候可以停

不是“好看”，而是：

- 25% 缩略图能读出主体和场景；
- 第一眼只有一个主焦点；
- 主体轮廓/连接/接触能解释；
- 没有未覆盖的透明区；
- 同一 plan 重渲逐像素一致。

审美判断仍然由人/任务意图决定；这份笔记不提供分数。

## 5. 不要把这些写成默认流程

- 不要求先出三张缩略图；
- 不要求固定层数、固定层名、固定笔刷；
- 不要求“必须先铺底再细节”；
- 不把“三分法/引导线”写成合格线；
- 不把这份笔记塞进 SKILL 默认入口。

它只是可选的观察清单，和 driver 接口分开。
